# n8n workflow

File: [`n8n/whatsapp-ecommerce-agent.workflow.json`](../n8n/whatsapp-ecommerce-agent.workflow.json), generated by [`scripts/build-n8n-workflow.ts`](../scripts/build-n8n-workflow.ts) (`npm run build:workflow`). Don't hand-edit the JSON. Edit the generator so the OpenAI prompt and schema stay identical to the backend. CI fails on drift.

Tested by importing, publishing and executing it on **n8n 2.20.12** (Docker image `n8nio/n8n:2.20.12`) in DEMO_MODE. Older 1.x versions should import it (node versions: Webhook 2, Code 2, HTTP Request 4.2, Switch 3.2) but have not been tested.

## Node map

```
Inbound Turn (from Gateway)      Webhook, header auth, responds 200 immediately
 └ Validate Envelope             Code: schema check, tools base URL
   └ Get Conversation Context    tool: context (3 tries)
     └ Handoff / Classifier Switch
        ├0 handoff active ─────────────────────────────┐
        ├1 non-text message ───────────────────────────┤
        ├2 DEMO → HubSpot: Upsert Contact (DEMO mock)  │
        │        → Mock Classifier (DEMO rules) ─┐     │
        └3 live → HubSpot: Upsert Contact        │     │
                 → Build OpenAI Request          │     │
                 → OpenAI: Classify Intent ──────┤     │
                    (error) → Rule Fallback ─────┤     │
                              Normalize Classification │
                              └ Route (Server Guard) ◄─┘
                                └ Route Switch
                                   ├0 WooCommerce: Search Products ──────────┐
                                   ├1 WooCommerce: Verify Ownership & Get Order
                                   ├2 HubSpot: Create Ticket & Handoff ──────┤
                                   ├3 (static reply) ────────────────────────┤
                                   └4 (none) → Complete Turn                 │
   any tool error → Safe Fallback: Escalate Tool Error (1 try)               │
                     (error) → Static Technical-Issue Reply ─────────────────┤
                                                              Has Reply? ◄───┘
                                                               ├ WhatsApp: Send Reply (3 tries, idempotent)
                                                               └ Complete Turn (Log) / Complete Turn (Error Log)
```

The workflow holds **no third-party credentials except OpenAI**. WooCommerce, HubSpot and WhatsApp calls go through the gateway's tool API, which enforces ownership checks, the 24-hour window and idempotency. Even a compromised workflow cannot read arbitrary orders or message arbitrary numbers.

## Import (UI)

1. n8n → **Workflows → Import from File** → select the JSON.
2. Create the three credentials from [credentials.md §5](credentials.md#5-n8n-credentials). Then open each node with a red credential warning and select the credential, or rely on the matching names.
3. In **Validate Envelope**, set `DEFAULT_TOOLS_BASE_URL` to where n8n can reach the gateway (for example `http://gateway:3000` in Docker or `https://gateway.internal`). Alternatively set env `SYNVOCA_TOOLS_BASE_URL` on n8n with `N8N_BLOCK_ENV_ACCESS_IN_NODE=false`.
4. In **Build OpenAI Request**, set `MODEL` if you don't use `gpt-5-mini`.
5. **Publish / activate** the workflow. Copy the production webhook URL (`…/webhook/synvoca-whatsapp-turn`) into the gateway's `N8N_INBOUND_WEBHOOK_URL` and set `ORCHESTRATOR=n8n`.
6. Recommended: **Settings → Error workflow**, to alert someone when an execution fails (for example the gateway is unreachable).

## Import (CLI, as used for verification)

```bash
ORCHESTRATOR=n8n docker compose --profile n8n up -d --build
docker compose exec n8n n8n import:credentials --input=/import/demo-credentials.json   # DEMO values only
docker compose exec n8n n8n import:workflow   --input=/import/whatsapp-ecommerce-agent.workflow.json
docker compose exec n8n n8n publish:workflow  --id=synvocaWaAgent01
docker compose restart n8n            # CLI changes apply after restart
```

Then send scenarios from the dashboard at http://localhost:3000 (traces show `n8n.forward_turn`) or with `npm run simulate`.

## Design notes

- **AI suggests, server decides.** `Route (Server Guard)` validates the classification and returns exactly one route plus all parameters. The Switch only follows it.
- **No loops.** The graph is acyclic (a test checks this). Retries are per node and capped at 3.
- **Idempotent retries.** Re-running *WhatsApp: Send Reply* cannot double-send (one reply per inbound message id). Re-running *Create Ticket* cannot open a second ticket while a handoff is active.
- **Privacy.** Successful executions are not saved (`saveDataSuccessExecution: none`). Error executions are saved for debugging and pruned by `EXECUTIONS_DATA_MAX_AGE`.
- **Why not the n8n "AI Agent" node?** A free-running tool-calling agent lets the model choose tools and arguments. Here the model only classifies, and a deterministic, tested guard picks the tool, which removes the fabrication and prompt-injection risks for order data. If you want the agent node, connect it only to the gateway's `/tools/*` endpoints, which keep enforcing the same rules.
